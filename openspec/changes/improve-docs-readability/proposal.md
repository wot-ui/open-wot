## Why

文档网站的描述文字、导航辅助信息和表格内容在深色背景下显得灰暗，同时全屏扫描线覆盖正文，导致文字边缘发糊、长时间阅读费力。需要在保留现有深色终端风格的前提下，移除正文阅读干扰并建立可验证的文字对比度标准。

## What Changes

- 提高文档页正文、描述文字、列表、表格内容和关键辅助信息的颜色对比度，建立清晰的正文与次要信息层级。
- 从文档阅读区域移除扫描线覆盖效果，避免条纹直接叠加在文字上；终端视觉语言继续通过背景、代码块和装饰元素表达。
- 为正文、导航、搜索提示、表头、链接和交互状态定义最低对比度要求，并覆盖自定义主题色场景。
- 调整文档页的字体分工：正文优先使用适合中文阅读的系统无衬线字体，代码、命令和终端标签保留等宽字体。
- 补充桌面端与移动端的定向可读性检查，运行官网 lint 与 build 验证。
- 不修改 `README.md` 文档内容，不改变文档搜索、目录生成或复制代码的功能行为。

## Capabilities

### New Capabilities

- `docs-readability`: 规定文档网站正文、辅助文字、扫描线装饰、主题色和不同视口下的可读性要求。

### Modified Capabilities

- 无。

## Impact

- 主要影响 `apps/website/app/globals.css` 中 `/docs` 页面使用的视觉样式。
- 可能需要小范围调整 `apps/website/app/docs/page.tsx` 或 `apps/website/public/theme.js`，用于隔离装饰层或保证自定义主题色对比度；不改变公开数据结构和交互契约。
- 官网 `/docs` 的视觉表现受到影响；官网首页、`README.md` 内容源、CLI 输出、MCP 契约、离线数据和 Skills 均不受影响。
- 不引入破坏性变更，不新增运行时依赖。
